# content-repurpose

> **문구를 새로 쓰지 않는다. 쪼개고, 맡기고, 순서를 짜고, 닿게 만든다.**

블로그 글 한 편을 **카카오톡 채널 · 오픈 채팅방 · 인스타그램 · 스레드 · 유튜브**에 나눠 발행하고,
쌓인 글 3~5편 — 또는 **폴더 안의 글** — 을 **뉴스레터 한 통**으로 묶는 Claude 스킬입니다.

```
모드 A · 새 글       원본 1편   →  원자 3~7개  →  카톡 채널 · 오픈 채팅방 · 인스타 · 스레드 · 유튜브
모드 B · 정리        원본 3~5편 (또는 폴더)  →  뉴스레터 한 통  →  다시 원본으로
```

## v2 에서 바뀐 것 (2026-09)

| | |
|---|---|
| **유튜브** | 영상 · 쇼츠 · 게시물을 나눠서 — 제목 후보 · 설명(챕터 포함) · 태그 · 고정 댓글에 더해 **업로드 화면에서 고를 것**(아동용 여부 · AI 표시 · 관련 동영상 …)을 체크리스트로 |
| **폴더 → 뉴스레터** | 폴더를 주면 그 안의 글을 읽어 목록부터 보여주고, 골라서 한 통으로 묶는다 |
| **도구별 뉴스레터 모양** | 일반 글 · 편집기형(스티비 등) · 마크다운 · 직접 만든 화면 — `account.md` 에서 고른다 |
| **링크는 가진 주소 그대로** | 기본은 내가 가진 주소를 그대로 넣는다. 꼬리표 · UTM · 짧은 링크는 `account.md` 에 적은 사람만 (선택) |
| **주기 · 일정표는 고르는 칸** | 뉴스레터 주기 · 정기 발행 요일 · 발행 뒤 체크할 일정표 — 비워 두면 그 단계를 건너뛴다 |

첫 공개본(2026-09-10)은 `v1` 태그로 남아 있습니다.

## 영문 리퍼포징 스킬과 무엇이 다른가

리퍼포징 스킬은 이미 있습니다(`crosspost` · `content-repurposing` · `social`). 전부 영문이고,
**카카오톡과 네이버 블로그를 다루지 않습니다.** 이 스킬은 그 빈자리에 있습니다.

### 한국 채널의 실제 제약 — 검색해도 잘 안 나오는 것

- **오픈 채팅방 공지는 약 500자에서 「전체 보기」로 접힌다.** 줄 수가 아니라 글자 수 기준이다 → 400자 안으로
- **카톡 채널 소식은 사진과 링크 중 하나만** 넣을 수 있다
- **링크 미리보기 카드는 첫 번째 링크 하나에만** 붙는다. 오픈 채팅방 **공지에는 아예 안 붙는다**
- **카톡 채널 소식은 알림이 가지 않는다.** 푸시는 유료 메시지에만 붙는다
- **사업자 정보 미확인 카톡 채널은 「전문의」 같은 자격 표기가 막힌다**
- **채팅은 두 곳에서 꺼야 한다** — 채널홈 카드와 채팅 설정은 다른 것이다
- **네이버 상단메뉴에는 외부 링크를 못 넣는다** → 위젯. 그런데 **위젯은 PC 에만 보인다**
- **og:image 없이 한 번 뿌리면** 「이미지 없음」이 캐시되고 **카카오는 갱신 도구가 없다**
- **다른 곳에 쓴 문장을 블로그로 가져오면** 네이버가 중복 문서로 판정해 글 전체를 묻는다

### 「글 하나 → 채널 넷」이 아니라 「글 하나 → 원자 → 채널」

글을 **원자**(논지 · 핵심 포인트 · 일화 · 수치 · 인용문 · 실행 항목)로 쪼개고,
채널마다 **다른 원자를 맡깁니다.** 네 곳을 다 구독한 사람이 같은 내용을 네 번 보지 않습니다.

어느 원자를 어느 채널에 맡길지는 **다섯 항목으로 채점**합니다 —
훅 · **홀로서기** · 감정 · 정보밀도 · 마무리. 잘라낸 조각이 원문 없이도 서는지(홀로서기)가
리퍼포징 실패의 대부분이라, 감점 신호를 명시해 두었습니다.

## 설치

**클로드 코드** — 이 저장소를 스킬 폴더로 받습니다.

```bash
git clone https://github.com/yunna-kim/content-repurpose ~/.claude/skills/content-repurpose
```

**claude.ai** — 설정 → 사용자 지정 → 스킬 → 추가 → 스킬 업로드에서 `.skill` 파일을 올립니다.
`.skill` 은 이 폴더를 zip 으로 묶은 것입니다 (최상위에 `content-repurpose/` 폴더 하나).

### 처음 한 번 — 내 값을 채운다

```
references/account.example.md  →  복사해서 references/account.md
references/tone.example.md     →  복사해서 references/tone.md    (선택)
```

`account.md` 에는 **내 채널 주소 · 쓰는 채널 · 부를 스킬**(유입 꼬리표 · 짧은 링크는 선택)을 적습니다.
**안 채워도 됩니다** — 없으면 스킬이 처음 쓸 때 한 번 묻습니다.

말투 파일(`voice.md`)이 따로 있으면 같은 `references/` 에 두세요. 스킬이 읽습니다.

### 같이 쓰면 좋은 스킬

문구는 채널 스킬이 있으면 불러 씁니다. **없어도 돌아갑니다** — 최소 규칙으로 직접 씁니다.

| 채널 | 예 |
|---|---|
| 블로그 (원본 쓰기) | `blog-writing` |
| 스레드 | `threads-writing` |
| 인스타 캐러셀 · 유튜브 게시물 이미지(1:1) | `cardnews` · 캐러셀 스킬 |

## 파일

```
SKILL.md                      순서와 판단 — STEP 0~9
SOURCES.md                    어디서 무엇을 가져왔나
references/
  channels.md                 채널별 제약 사전                    ← 이 스킬의 자산
  youtube.md                  유튜브 영상 · 쇼츠 · 게시물 — 글과 업로드 화면 체크리스트
  atoms.md                    원자 여섯 종과 뽑는 법
  scoring.md                  채점표 · 채널별 가중치
  newsletter.md               뉴스레터 규격 (한국 법·메일 환경 반영)
  reach.md                    길이 · 첫 10분 · 네이버 SEO · 인스타 검색 · GEO·AEO
  publish-check.md            링크 미리보기 · 꼬리표 · 발행 순서 · 48시간
  carousel.md                 캐러셀 스킬이 없을 때만
  account.example.md          내 값 틀
  tone.example.md             카톡 · 오카방 · 인스타 캡션 · 유튜브 · 뉴스레터 톤 틀
```

## 다루지 않는 것

| | 어디로 |
|---|---|
| 주제 찾기 | 주제 발굴 스킬 |
| 원본을 처음부터 쓰기 | 블로그 글쓰기 스킬 |
| 보도자료 · 신문 기사 | 보도자료 스킬 |
| 규제 업종(의료 · 금융 등) 표현이 적법한지 | 그 업종용 검수 스킬 — **이 스킬은 판정하지 않습니다** |

## 출처

스폰지클럽 3기 스킬러스 공유 저장소의 스킬 50개를 읽고 규칙을 가져왔습니다.

문장을 옮기지 않고 규칙과 구조만 가져왔으며, 원 저작자와 라이선스는 각 원본을 따릅니다.
